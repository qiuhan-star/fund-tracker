# 代码思路

## 数据流

```
localStorage('ft_data') ←→ silentSave() / loadData()
                           ↓
                        compute()  →  buildFundsView()  →  render()
                           ↓
                   ensureNavlessHist()  （异步补净值）
```

每次数据变更流程：`save()` → `silentSave()` → `compute()` → `render()`

---

## 核心数据结构

### 持仓快照 `snaps[]`
```js
{name, cat, mv, ret, account, code}
```
- `cat`：基金分类（股票/债券/混合/货币/黄金/商品/其他）
- `mv`：手动填写的市值
- `ret`：手动填写的收益率

### 交易记录 `trades[]`
```js
{name, account, date, time, type, amount, nav, shares, fee, confirm, locked, note, dcaId, dcaPeriod, convertTarget, pairId}
```
- `type`：buy / sell / dca / dividend / reinvest / convert / convert_out / split / activity
- `confirm`：`confirmed`(已确认) / `pending`(待确认) / `cancelled`(撤单)
- `locked: true`：锁定不可编辑（定投/CSV导入）
- `dcaId`：定投计划ID（有值说明是自动补记的定投交易）
- `pairId`：转换配对ID（convert 和 convert_out 成对出现）

### 定投计划 `dcaPlans[]`
```js
{id, name, account, amount, period, day, weekday, start, end, paused, createdAt}
```
- `period`：`month` / `week` / `biweek` / `twoweek`
- `day`：每月的几号（period=month）
- `weekday`：周几（period=week/twoweek）

### 净值缓存 `navCache{}`
```js
{"基金名": {nav, chg, gsz, gszzl, updateTime}}
```

## 定投逻辑

1. **自动补记**：`runDcaPlans()` 每天检查所有未暂停的定投计划，到日自动补一笔 `type:'dca'` 的交易
2. **默认状态**：`confirm:'pending'`（待确认），因为QDII基金有确认周期
3. **一键确认**：点击"一键确认" → `autoFillDcaTrade()` 拉历史净值补填 `nav` 和 `shares`，改为 `confirmed`
4. **确认日期**：`calcTradeDates()` 根据交易时间(15:00前/后)和是否QDII计算确认日期
5. **不补净值**：`ensureNavlessHist()` 跳过 `dcaId` 的交易（保持待确认）

---

## 交易记录思路

1. **存储原始值**：用户填写的 `amount`、`nav`、`shares` 原样存储，不修改
2. **计算不污染**：`buildFundsView()` 计算持仓时，用实时净值反推份额只用于计算，**不写回存储**
3. **历史净值补填**：缺净值时用 `ensureNavlessHist()` 拿交易日期对应的历史净值补填，不是今天的实时净值
4. **脏数据检测**：如果某个交易的 `nav` 等于今天实时净值，说明是旧版自动填充的脏数据，清空后由历史净值补填逻辑重新计算
5. **锁定保护**：`locked: true` 的交易（定投/CSV导入）不可编辑，防止误改
6. **撤单排除**：`confirm: 'cancelled'` 的交易不参与任何计算

## 持仓计算（平均成本法）

`buildFundsView()` 内对每个基金：

1. 过滤 `confirmed` 交易，按日期排序
2. 遍历每笔交易：
   - **买入**：`shares += t.shares`，`cost += t.amount + t.fee`
   - **卖出**：按加权平均扣减 `shares -= t.shares`，`cost -= avgCp * t.shares`
   - **分红**：`realized += t.amount`（现金分红，不影响持仓成本）
   - **红利再投**：`shares += t.shares`，`cost += t.amount`
   - **拆分**：`shares *= ratio`
3. 持仓成本 = `cost / shares`
4. 持有收益 = `(liveNav - 成本) * shares`
5. 收益率 = `持有收益 / cost * 100%`

## 净值补填逻辑

`ensureNavlessHist()` 处理缺净值的 `confirmed` 交易：

1. 判断条件：交易日期已过结算日（今天或之前）
2. 通过基金代码拉取历史净值 `fetchNavHistory(code)`
3. 按交易日期（15:00后算次日）找到对应历史净值
4. 补填 `t.nav` 和 `t.shares`（`amount / nav`）
5. 跳过 `pending`、`cancelled`、`dcaId` 的交易

## 账户体系

- **内置账户**：本人账户(isPersonal) / 投资账户(isPersonal) / 代管账户(!isPersonal)
- **旧名映射**：支付宝/我的 → 本人账户，微信债券/微信 → 投资账户，小号 → 代管账户
- **自定义改名**：`ACC_RENAME_MAP` 持久化到 `localStorage('ft_acc_rename')`
- **口径过滤**：`scopeMatches()` 判断是否匹配当前筛选口径
